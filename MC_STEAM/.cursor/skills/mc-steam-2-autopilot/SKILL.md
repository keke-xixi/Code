# MC_STEAM「2」自主优化（约 4 小时）

## 触发

用户单独发送 **`2`**（或明确说「跑 2 skill / 四小时优化」）时，**立即阅读本 skill** 并开始执行。工作目录：`MC_STEAM/`（Godot 4 挖矿项目）。

## 总目标

在约 **4 小时**预算内自主改进游戏：**手感、性能、UI 简洁度、音效反馈、明显 bug**，优先「玩家一眼懂、操作顺」。

## 进度条（必须对用户可见）

每完成一个阶段或至少 **每 25–35 分钟**主动回复一次，格式固定：

```markdown
## 自主优化进度
[████████░░░░░░░░] 52% · 约 2h05m / 4h
**当前**：<正在做什么>
**已完成**：<1–3 条>
**下一步**：<1 条>
```

- 百分比 = 已完成阶段数 ÷ 计划阶段数（默认 8 阶段，可调）。
- 时间用「约已用 / 4h」估算即可，不必精确计时。
- 用 `TodoWrite` 维护阶段清单，每完成一项标记 done 并发进度条。

## 执行原则

1. **先读** `MC_STEAM/README.md`、`scripts/main.gd`、`game_session.gd`，再动刀。
2. **小步提交式改动**：每阶段聚焦 1–2 主题，避免一次改全库。
3. **游戏 UI**：短文案、大图标、少段落；避免说明书式弹窗。
4. **不擅自 git commit**；除非用户明确要求。
5. 每阶段结束 **自检**：Godot 脚本无 Parser Error、路径 `MC_STEAM/` 一致。
6. 用户中途插话则以用户为准，完成后继续进度条。

## 默认 8 阶段（按序，可跳过已完成）

| # | 阶段 | 要点 |
|---|------|------|
| 1 | 手感 | 移动/挖矿并行、输入、镜头 |
| 2 | 性能 | 绘制范围、FX 分层、存档节流 |
| 3 | 商店/UI | 弹窗极简、滚轮隔离、游戏风 |
| 4 | 反馈 | 音效、碎屑、震动强度 |
| 5 | 数值 | 镐子/矿物耗时可读性 |
| 6 | HUD | 提示一行化、连击/深度 |
| 7 | 设置/存档 | O 设置、F5、边界情况 |
| 8 | 收尾 | README 更新、已知问题列表 |

详细 backlog 见 [backlog.md](backlog.md)。

## 开场回复模板

开始执行时第一条消息必须包含：

```markdown
已启动「2」自主优化（目标约 4h）。我会按阶段推进并定期发进度条。
[█░░░░░░░░░░░░░░░] 6% · 约 0h05m / 4h
**当前**：盘点 MC_STEAM 现状
```

## 结束

8 阶段完成或用户叫停时，发最终进度条 100% + **变更摘要**（玩家能感知到的 3–5 条）。
